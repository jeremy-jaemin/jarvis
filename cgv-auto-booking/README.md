# CGV 좌석 자동 확보

매진된 CGV 상영회차에서 취소표가 나오면 즉시 좌석을 잡고 **결제수단 선택 페이지까지 진입한 뒤 멈추는** 도구.
쿠폰 적용과 최종 결제는 사람이 직접 한다.

cmux 브라우저 CLI로 실제 브라우저 세션을 조작한다. 로그인 세션을 그대로 쓰므로 별도 인증이 없다.

## 왜 만들었나

CGV 웹 예매 UI에는 자동화를 조용히 실패시키는 함정이 여러 개 있다.
좌석 모달을 다시 열어도 데이터가 갱신되지 않는다든지, 새로고침이 관람인원 선택을 매번 초기화한다든지,
`결제하기` 버튼이 사실 2개라 첫 번째를 누르면 영원히 이동하지 않는다든지.
전부 실측해서 [`docs/FINDINGS.md`](docs/FINDINGS.md)에 정리했다. **코드보다 이 문서가 핵심이다.**

## 요구사항

- [cmux](https://cmux.app) (브라우저 자동화 CLI)
- `jq`
- CGV 로그인된 브라우저 서피스

## 사용법

### 1. 예매 페이지까지 직접 이동한다

**반드시 정상 흐름으로 들어가야 한다.**

```
cgv.co.kr/cnm/movieBook/movie  →  영화  →  극장  →  회차 클릭
```

`/cnm/selectVisitorCnt?coCd=...` 같은 딥링크로 진입하면 좌석 선택까지는 되지만
결제 페이지가 `결제 수단을 불러올 수 없습니다`로 깨진다.

### 2. 설정을 만든다

```bash
cp config.example.json config.json
```

좌석 API는 **자동으로 탐지한다.** 핸터가 새로고침(↻) 요청을 가로채
`/api/v1/booking/searchIfSeatData` URL을 알아내므로 직접 지정할 필요가 없다.
굳이 고정하고 싶으면 `api`에 쿼리 파라미터를 직접 넣는다.

| 키 | 설명 |
|---|---|
| `personType` / `personCount` | 관람인원. `"일반"` 1~4매 |
| `targetRows` | 노릴 열. `["I".."P"]`처럼. `null`이면 전체 |
| `rowRank` | 열 선호도. 값이 낮을수록 우선 |
| `preferAdjacent` | 2매 이상일 때 연석 우선 |
| `refreshMs` | 좌석 API 갱신 주기. 1회당 약 35KB |
| `autoPay` | `false`면 좌석만 잡고 결제로 넘어가지 않는다 |

### 3. 실행한다

```bash
bin/run.sh surface:41 config.json     # 핸터 주입
bin/watch.sh surface:41               # 감시 (별도 터미널)
```

서피스 번호는 `cmux browser --surface surface:N get-url`로 찾는다.

좌석을 잡으면 감시자가 `SECURED` 로그와 `secured.png`를 남기고 종료한다.
브라우저는 결제수단 선택 페이지에 멈춰 있다. 여기서 쿠폰을 적용하고 결제를 마무리하면 된다.

## 동작

```
매 refreshMs:  새로고침(↻) 클릭 → 좌석 API 갱신 → 관람인원 재선택
매 scanMs +    빈 좌석 스캔 → 조건에 맞으면
DOM 변경 시      ├ 새로고침·예약된 인원클릭 즉시 차단
                 ├ 좌석 클릭
                 ├ 결제 버튼 활성화 즉시 클릭 (8ms 백업 루프 + MutationObserver 동기 처리)
                 ├ "결제 전 확인해 주세요" 시트의 결제하기 클릭
                 └ 결제수단 페이지 도달 → 정지
```

좌석 클릭에서 결제 클릭까지 실측 **53~122ms**.

## 설계상 중요한 것

- **좌석을 잡는 즉시 새로고침과 예약된 인원 클릭을 취소한다.** 전환 도중 관람인원 버튼이 눌리면
  좌석 선택이 초기화되어 결제 페이지가 `0원` + 결제수단 로드 실패로 열린다.
- **`결제하기` 버튼은 마지막 매치를 눌러야 한다.** 확인 시트가 열리면 같은 텍스트의 버튼이 2개가 되고,
  첫 번째는 시트에 가려진 원래 버튼이다.
- **연타 금지.** 이동이 안 된다고 빠르게 반복 클릭하면 진행 중인 처리가 계속 리셋된다. 1초 이상 간격을 둔다.
- **확보 직후에 검증을 넣지 마라.** 좌석 점유는 수십 초면 풀린다. 결제 페이지까지 간 다음에 확인한다.
- 핫 루프에서는 `innerText` 대신 `textContent`를 쓴다 (리플로 유발, 약 9.5배 차이).
- 비활성 탭의 `requestAnimationFrame`은 33ms로 제한된다. 빠른 폴링은 `setTimeout(fn, 8)`.

## 한계

- 클래스 해시(`cnms01520_*`, `numberChoice_NumberWrap__*` 등)는 CGV 배포마다 바뀔 수 있다.
  대부분 부분 일치 선택자를 쓰지만 `.numberChoice_NumberWrap__JKTv1`은 정확 일치라 깨지기 쉽다.
- 페이지가 리로드되면 핸터가 사라진다. 감시자가 알려주면 `bin/run.sh`를 다시 실행한다.
- 딥링크 복구가 불가능해 페이지 이탈 시 자동 복귀를 하지 않는다. 수동으로 흐름을 다시 타야 한다.
- 좌석 점유가 풀린 뒤에는 CGV가 세션을 마이페이지로 튕겨낸다.
- API가 판매 가능(`seatSaleYn="Y"`)이라 해도 실제로는 선택할 수 없는 좌석이 있다(실측 200석 중 54석).
  그래서 탐지 기준은 API가 아니라 DOM의 `seatDisabled` 클래스다. 자세한 내용은 FINDINGS §1-1.

## 하지 않는 것

최종 결제는 자동화하지 않는다. `autoPay: true`여도 결제수단 선택 페이지에서 멈춘다.
할인·쿠폰 적용이 사람 판단이고, 잘못 눌리면 실제로 돈이 나가기 때문이다.
