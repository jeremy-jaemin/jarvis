# CGV 웹 예매 리버스 엔지니어링 노트

2026-09-06, `cgv.co.kr` 신규 UI(Next.js SPA) 기준. 실제 예매를 돌리며 하나씩 실측한 내용이다.
클래스 해시(`cnms01520_*`, `seatMap_*` 등)는 빌드마다 바뀔 수 있으므로 항상 부분 일치 선택자를 쓴다.

---

## 1. 좌석 API

```
GET /api/v1/booking/searchIfSeatData
      ?coCd=A420        # 회사 코드
      &siteNo=0013      # 극장 (0013 = 용산아이파크몰)
      &scnYmd=20260906  # 상영일
      &scnsNo=018       # 상영관 (018 = IMAX관)
      &scnSseq=5        # 회차
      &seatAreaNo=001&cusgdCd=01&custNo=...
```

응답 `data.items[0].seats[]`의 좌석 객체에서 실제로 쓸 필드:

| 필드 | 의미 |
|---|---|
| `seatLocNo` | 좌석 고유 ID. DOM의 `data-seatlocno`와 1:1 대응 |
| `seatRowNm` | 열 문자 (`A`~`P`) |
| `seatNo` | 열 내 번호. **`seatColNm`이 아니다** |
| `seatSaleYn` | `"Y"`면 예매 가능 |
| `seatSalfrmCd` | `"04"`면 장애인석 |
| `seatStusNm` | `판매`(팔림) / `진행`(누군가 예매 진행 중) / `미정` |

측정값: 전송 **35KB**(gzip), 압축 해제 **543KB**, 응답 **약 130ms**.
압축 후가 작아서 1초 주기 폴링도 부담이 크지 않다.

`seatStusNm === "진행"`은 누군가 좌석을 잡고 결제 흐름에 있다는 뜻이다.
내가 잡은 좌석도 이 상태가 되며, **내 세션이 잡고 있는 동안엔 내 화면에서도 매진으로 보여 다시 선택할 수 없다.**

---

## 1-1. `seatSaleYn === "Y"`는 "선택 가능"이 아니다 ★

API가 판매 가능(`Y`)이라고 해도 화면에서 선택할 수 없는 좌석이 상당수 있다.

실측 (스파이더맨 6관, 200석, 관람인원 1명):

| | 개수 |
|---|---|
| API `saleYn=Y` + DOM 선택 가능 | 146 |
| API `saleYn=Y` + DOM `seatDisabled` | **54** |

두 존(`일반존`/`Light존`) 모두에서 나타나므로 존 문제가 아니다.
CGV가 좌석 간격 규칙 등으로 추가 제약을 거는 것으로 보인다.

**따라서 클릭 가능 여부의 기준은 DOM의 `seatDisabled` 클래스다.**
API의 `seatSaleYn`으로 탐지하면 클릭되지 않는 좌석을 잡았다고 오판한다.
API는 `seatLocNo → seatRowNm/seatNo` 매핑과 좌석 총수를 얻는 용도로만 쓴다.

## 2. 좌석 데이터는 새로고침 버튼으로만 갱신된다

- 갱신을 일으키는 것: `관람인원` 우측 **새로고침(↻) 아이콘**
  → `[class*=cnms01520_titleWrap] button.btn-icon`
- **좌석 모달을 닫았다 다시 여는 것은 네트워크 요청을 전혀 만들지 않는다.**
  캐시된 스냅샷을 다시 그릴 뿐이다. 모달 재오픈으로 폴링하면 영원히 새 좌석을 못 본다.
- 모달을 **열어둔 채** 새로고침을 눌러도 열린 모달의 좌석 DOM이 정상 갱신된다.

## 3. 새로고침은 관람인원을 매번 초기화한다

새로고침할 때마다 `관람인원` 선택이 풀린다. 그리고 **관람인원이 없으면 `선택완료`·`결제하기` 버튼 자체가 렌더링되지 않는다.**
따라서 폴링 루프는 매 새로고침 후 인원을 다시 선택해야 한다.

```
관람인원 행:  .numberChoice_NumberWrap__JKTv1   (textContent가 "일반"/"청소년"으로 시작)
숫자 버튼:    button.btn-num                    (선택 여부는 aria-pressed="true")
```

## 4. 좌석을 고른 뒤에는 관람인원을 절대 다시 누르지 마라

좌석 선택 후 인원 버튼을 다시 누르면 **좌석 선택이 초기화된다.**
새로고침 타이머가 예약해 둔 인원 재선택 `setTimeout`이 결제 전환 도중에 터지면
결제 페이지가 좌석 없이 열려 `최종결제금액 0원` + `결제 수단을 불러올 수 없습니다`가 된다.
**좌석을 클릭하는 즉시 새로고침 타이머와 예약된 인원 클릭을 모두 취소해야 한다.**

## 5. 좌석 클릭은 순수 클라이언트 동작

좌석 버튼 클릭은 네트워크 요청을 **0건** 발생시킨다. 서버 커밋을 기다릴 필요가 없다.

## 6. 결제하기 버튼은 2개다 ★ 가장 많이 헤맨 부분

`결제하기`를 누르면 곧바로 이동하지 않고 **"결제 전 확인해 주세요" 바텀시트**가 열린다.
이 시트 안에 **또 하나의 `결제하기` 버튼**이 있고, 그것을 눌러야 `/mpy/main`으로 이동한다.

```
시트가 열린 상태에서 텍스트가 "결제하기"인 버튼:
  idx  64  "9,000원 결제하기"   ← 페이지 (시트에 가려짐)
  idx 508  "결제하기"           ← 확인 시트 (이걸 눌러야 이동)
```

둘은 화면상 같은 위치에 겹친다.

- **첫 매치에서 return하면 안 된다.** 항상 마지막(= 최상단) 매치를 눌러야 한다.
  첫 매치만 누르면 원래 버튼을 계속 눌러 시트만 다시 열 뿐 영원히 이동하지 않는다.
  (실측: 250ms 간격 81회 클릭 21.8초 동안 이동 없음. 연타를 멈추고 마지막 버튼을 한 번 누르자 즉시 이동.)
- **연타 금지.** 진행 중인 처리가 계속 리셋된다. 재시도는 1초 이상 간격을 둔다.

## 7. 예매 세션은 정상 흐름으로 만들어야 한다

`/cnm/selectVisitorCnt?coCd=...&scnSseq=...` 같은 딥링크로 들어가면
좌석 선택까지는 되지만 결제 페이지가 `결제 수단을 불러올 수 없습니다`로 깨진다.

반드시 이 순서를 클릭해서 들어가야 한다:

```
/cnm/movieBook/movie  →  영화 선택  →  극장 선택  →  회차 버튼 클릭
   → /cnm/selectVisitorCnt (쿼리 파라미터 없음)
```

회차 버튼 선택자: `button.screenInfo_timeLink__45VfR`

## 8. 좌석 점유는 짧다

좌석을 잡으면 `진행` 상태가 되지만 수십 초 안에 풀린다.
풀리면 CGV가 세션을 마이페이지·알림 페이지로 튕겨내며 예매 상태가 통째로 사라진다.
**확보 직후 API 재조회나 스크린샷 같은 검증을 넣지 말고 곧바로 결제 페이지까지 진입하라.** 검증은 그 다음이다.

## 9. DOM 관련 함정

- `.seatMap_container__JuJ3A`는 **모달을 닫아도 DOM에 남는다.** 모달 열림 판정에 쓰면 안 된다.
- 좌석 버튼은 화면당 **2벌** 존재한다(메인 좌석표 + 미니맵). `data-seatlocno`가 중복되므로
  `style.width`가 큰 쪽(메인)만 남기고 dedupe해야 한다.
- 새로고침 직후 좌석 버튼의 `innerText`가 비는 경우가 있다.
  열/번호는 DOM 텍스트가 아니라 **API의 `seatLocNo → seatRowNm/seatNo` 매핑**으로 판정하라.
- 상태 클래스는 부분 일치로 본다: `seatDisabled`(선택 불가), `seatPreferential`(장애인석).

## 10. 성능

- `innerText`는 리플로를 유발한다. 핫 루프에서는 `textContent`를 써라.
  실측: 버튼 탐색 `innerText` **0.633ms** → `textContent` **0.067ms** (약 9.5배).
- 비활성 탭에서 `requestAnimationFrame`은 **33ms(30fps)로 제한**된다.
  빠른 폴링이 필요하면 `setTimeout(fn, 8)` 체인을 써라 (실측 평균 8.5ms).
- 가장 빠른 반응은 `MutationObserver`에서 **동기로** 처리하는 것이다.
- 좌석 클릭 → 결제 클릭 지연: 최적화 전 **약 550ms** → 최적화 후 **53~122ms**.

## 11. 안전

최종 결제는 자동화하지 않는다. 쿠폰·할인 적용은 사람이 직접 해야 하므로
**결제수단 선택 페이지(`/mpy/main`)에 도달하면 멈추고 넘긴다.**
